# 操作经验总结 · 风格补充

> 基础规范见 `../blog-common/base-style.md`。本文档仅描述「操作经验总结」品类特有的要求。

## 品类定义

聚焦**工具、框架、平台的实操经验**。以"我从使用中学到了什么"为主线，帮助读者快速上手、避坑、提升使用效率。

标杆文章：
- `source/_posts/claude-memory-insight.md`
- `source/_posts/claude-code-configuration-guide.md`

## 文章结构模式

```
1. 引入（个人经历/场景 → 引出工具或问题）
2. 为什么需要关注 X（价值说明，不必太长）
3. 核心概念/机制解释（快速建立认知）
4. 实操指南（核心章节，2-3节）
   ├── 基础用法（配置、命令）
   ├── 进阶技巧（模式、策略、高级功能）
   └── 踩坑记录（遇到的问题 + 解决方案）
5. 最佳实践案例（可选，如 PyTorch 的 CLAUDE.md）
6. Tips / Checklist
7. 总结（回顾 + 学习路径建议 + 相关文章推荐）
8. 参考资料
```

## 独特要求

- [ ] 开篇有个人使用场景或动机（建立亲和力）
- [ ] ≥3 处可运行的完整代码/配置示例（非片段）
- [ ] 概念解释要先给通俗比喻再给技术定义
- [ ] ≥1 处"对比"（Good vs Bad、A vs B 方案）
- [ ] Tips 集合（≥3 条实用建议）
- [ ] 总结中包含学习路径或渐进式建议
- [ ] 参考资料列表（URL 链接）

## 数据要求

- 配置项说明标注作用域（全局/项目/个人）
- 版本号标注兼容性范围（如「VS Code 1.109+」）
- 路径标注操作系统差异（macOS / Linux / Windows）

## 视觉元素侧重点

- `table-wrap`：配置项说明、功能对比、路径汇总（高频）
- `code block`：完整配置示例、命令（高频）
- `callout`：注意事项、关键提示
- `phase-card`：机制/概念解释
- （不使用 arch-grid、stack-diagram、policy-flow）

## 语言风格

- 口语化程度略高于洞察类，允许第一人称
- 先讲「什么时候用」再讲「怎么用」
- 允许主观评价（「这个功能很实用」「不太推荐」）
- 善用类比降低理解门槛
- 避免「显然」「毫无疑问」等绝对化表达
- 经验教训要说清楚前因后果（场景→问题→解决）

## 对洞察类的差异

| 维度 | 操作经验总结 | 技术项目洞察 |
|------|------------|------------|
| 主角 | 工具/平台 | 项目/产品 |
| 视角 | 使用者（我） | 分析者 |
| 核心 | 怎么用好 | 它是怎么做的 |
| 数据 | 配置参数、版本兼容 | 架构指标、社区数据 |
| 深度方向 | 场景覆盖度 | 机制理解深度 |
| 结论 | 学习建议 | 趋势判断 |
