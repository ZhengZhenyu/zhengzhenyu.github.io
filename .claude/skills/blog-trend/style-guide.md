# 业界趋势洞察 · 风格补充

> 基础规范见 `../blog-common/base-style.md`。本文档仅描述「业界趋势洞察」品类特有的要求。

## 品类定义

聚焦**行业宏观趋势、技术方向判断、格局变化**。从多源数据和多维视角出发，给出有依据的趋势判断。

此类文章目前尚无标杆，以下规范为设计标准——首次使用时可能需要迭代调整。

## 文章结构模式

```
1. 引言（信号捕捉 → 为什么现在值得关注 → 核心判断）
2. 现状全景（市场数据、关键玩家、格局地图）
3. 驱动力分析（技术、商业、政策/合规，多因素交织）
4. 关键变量/不确定性（什么可能改变走势）
5. 多方观点（不同立场的逻辑——不是罗列，是分析各自为什么这么看）
6. 趋势预判（核心章节：短期 1-2 年 + 中期 3-5 年 + 可能的转折点）
7. 对从业者的建议（不同角色的应对策略）
8. 结语（一句话核心判断收束）
```

## 独特要求

- [ ] 开篇必须给出核心判断（一句话，加粗），而非只描述现象
- [ ] ≥3 个独立数据源（不来自同一篇报道或报告）
- [ ] 驱动力分析不能是单因素——技术、商业、政策至少覆盖两个
- [ ] 有对立观点或不确定性的诚实呈现（不假装什么都确定）
- [ ] 趋势预判标注时间范围（短期/中期）和置信度（高/中/低）
- [ ] 对不同角色的差异化建议（如开发者、创业者、企业决策者）
- [ ] 后续值得关注的信号列表（什么发生时说明判断正确/错误）

## 数据要求

- 市场数据标注来源和时间
- 趋势图优先用 stats-grid 呈现关键数字（主要指标的对比更直观），大量时序数据可用 table-wrap
- 预测数据标注「预测」标签，区分事实与预测

## 视觉元素侧重点

- `verdict`：核心判断、趋势预判（高频）
- `callout`：多方观点、关键变量罗列
- `stats-grid`：关键市场数据
- `table-wrap`：格局对比、时间线、角色建议
- `phase-card`：驱动力展开
- （不使用 arch-grid、stack-diagram——趋势类不需要代码架构图）

## 语言风格

- 冷静、克制、留余地——趋势判断讲概率不讲绝对
- 多用「可能」「倾向于」「值得关注的是」而非「必然」「一定」「毫无疑问」
- 区分「事实陈述」「数据引用」「个人判断」三层
- 长句可以用于展开分析脉络，但核心判断必须短
- 允许使用比喻来简化复杂格局（如「淘金热里卖铲子」）
- 中文为主，但行业术语和机构名保留原文

## 与其他品类的差异

| 维度 | 趋势洞察 | 项目洞察 | 操作经验 |
|------|---------|---------|---------|
| 主角 | 行业趋势/方向 | 项目/产品 | 工具/平台 |
| 视角 | 观察者+判断者 | 分析者 | 使用者（我） |
| 时间框架 | 过去→现在→未来 | 现在（深度） | 现在（广度） |
| 核心 | 什么在发生、为什么、会怎样 | 它是怎么做的 | 怎么用好 |
| 确定性 | 概率性、多场景 | 确定性、可验证 | 确定性、可复现 |
| 结论 | 趋势判断+置信度 | 架构评价+趋势 | 学习建议+路径 |
